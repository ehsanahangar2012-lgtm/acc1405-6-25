# نقشهٔ تطبیق و مهاجرت نسخهٔ بومی اشک قلم

این پرونده معیار اجرای مهاجرت است. منبع تطبیق، نسخهٔ موجود در شاخهٔ `fix/core-data-integrity` و فایل‌های واقعی `App.tsx`، `components/Sidebar.tsx`، `store.ts` و سرویس‌های مرتبط است.

## قواعد غیرقابل‌تغییر

- توسعه فقط روی شاخهٔ `feature/windows-native-dotnet` انجام می‌شود؛ `main` و نسخه‌های فعلی وب، اندروید و Electron نباید تغییر کنند.
- این نسخه برنامه‌ای مستقل و موازی است. تا وقتی آزمون تطبیقی و تأیید انجام نشده، نسخهٔ فعلی باید قابل استفاده بماند.
- رابط نهایی باید WPF بومی باشد؛ از WebView/Chromium برای نمایش رابط استفاده نمی‌شود.
- هیچ گزینهٔ صدور لایسنس، مدیریت کلاینت، ساخت EXE/APK یا ابزارهای مختص «نسخهٔ مادر وب» نباید در برنامهٔ مشتری ویندوز قرار بگیرد. ویندوز فقط مصرف‌کنندهٔ سرویس اتصال/اعتبارسنجی لایسنس است.
- ماژولی تا وقتی منطق داده، اعتبارسنجی‌ها، مجوزها، رفتارهای خطا و آزمون‌هایش منتقل نشده‌اند، «تکمیل‌شده» علامت نمی‌خورد. ظاهر یا پیوند منو به‌تنهایی مهاجرت قابلیت نیست.
- هیچ مهاجرت خودکاری روی داده‌های کاربر انجام نمی‌شود تا تبدیل‌گر و آزمون برگشت‌پذیر/پشتیبان آن آماده باشند.

- [ ] انتقال کامل چرخهٔ فاکتور اصلی: ویرایش همهٔ وضعیت‌ها، قالب چاپ کامل و امضاشده، چک‌ها و روش‌های تسویه با دفترکل، سفارش/پیش‌فاکتور و گزارش‌های مالی دقیقاً مطابق نسخهٔ اصلی.

- [x] کلاینت WPF برای دریافت کلید عمومی و اعتبارسنجی آنلاین رسید امضاشدهٔ لایسنس به مرجع HTTPS اصلی اضافه شد؛ نگهداری وضعیت تأییدشده با DPAPI هم افزوده شده است. [ ] احراز هویت کامل، اعمال سهمیه روی تمام عملیات، ابطال/تازه‌سازی مداوم، sync، صف آفلاین و APIهای تجاری هنوز باز هستند.
- [ ] آزمون‌های رگرسیونِ مبتنی بر رفتار نسخهٔ اصلی و آزمون روی Windows واقعی.

## افزوده‌های اخیر — ۲۳ اکتبر ۲۰۲۶

- [x] دفتر دوبل بومی با کدینگ سرفصل، ثبت دستی سند، تراز آزمایشی و CSV.
- [x] مدل‌های جدید دفتر در فایل رمزگذاری‌شده موجود؛ فیلدهای اختیاری جدید به‌صورت پیش‌فرض مقداردهی می‌شوند تا JSON قدیمی با SchemaVersion=1 قابل خواندن بماند.
- [x] کلاینت لایسنس WPF در HTTPS: کلید عمومی SPKI، امضای RSA-PKCS#1 v1.5/SHA-256، تطبیق کلید/فضای کاری/HWID/طرح/سهمیه/تاریخ؛ فایل وضعیت فقط با DPAPI کاربر ذخیره می‌شود.
- [x] آزمون‌های واحد جدید برای دفتر دوبل، رسیدهای امضاشده و ذخیرهٔ وضعیت لایسنس اضافه شده‌اند.
- [ ] نتیجهٔ نهایی CI روی آخرین کامیت و آزمون میدانی روی رایانهٔ مالک هنوز تأیید نشده است؛ build و ۶۲ آزمون در یک اجرای قبلی موفق بودند اما smoke test اجرای EXE با خطای خروج ناگهانی شکست خورد و باید علت در اجرای بعدی ثبت/رفع شود.
- [ ] رسید ذخیره‌شده فقط آخرین وضعیت بررسی را نشان می‌دهد؛ در شروع برنامه اعتبار آنلاین دوباره بررسی می‌شود و سهمیه نسخه پایه به عملیات ثبت اصلی متصل شده است. پوشش همهٔ عملیات/قابلیت‌ها، ابطال فعال در سرور و همگام‌سازی هنوز کامل نیست.
- [ ] HWID به‌صورت پورت الگوریتم Electron بازسازی شده؛ تطبیق دقیق بین ترتیب آداپتورهای سیستم‌عامل‌ها باید با دستگاه واقعی/فرایند صدور لایسنس تأیید شود.

## ترتیب ادامهٔ کار

1. تثبیت پوستهٔ WPF و آزمون مسیرهای ناوبری.
2. تکمیل تطبیقی هستهٔ تراکنش‌ها: اشخاص، کالا، فاکتور، دریافت/پرداخت، چک و قواعد انبار.
3. انتقال موتور حسابداری و گزارش‌های اصلی؛ ارقام باید روی مجموعه‌دادهٔ آزمون با نسخهٔ اصلی برابر باشند.
4. انتقال احراز هویت/مجوزها و APIهای سرور بدون قرار دادن اسرار یا کلید خصوصی در EXE.
5. انتقال بقیهٔ ماژول‌ها بر اساس وابستگی، همراه آزمون واحد و رگرسیون.
6. آزمون نصب/ارتقا/پشتیبان/بازیابی روی Windows و بسته‌بندی؛ تصمیم جایگزینی فقط پس از تأیید کاربر.

## منبع تطبیق

- `App.tsx`: تعریف مسیرها و پوستهٔ برنامه.
- `components/Sidebar.tsx`: نام منوها، گروه‌بندی و محدودیت‌های نسخهٔ کلاینت/پرتال مادر.
- `store.ts`, `types.ts` و `services/*`: مدل‌های داده، قواعد و رفتارهای تجاری که باید قبل از انتقال هر ماژول بازرسی شوند.
