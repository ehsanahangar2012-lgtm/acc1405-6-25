# اشک قلم — نسخهٔ بومی Windows / WPF

این نسخه برنامهٔ دسکتاپ بومی WPF است؛ برای رابط کاربری از Electron، Chromium یا WebView استفاده نمی‌کند. GitHub Actions برای همین شاخه فقط restore/build/test و smoke-test اجرای کوتاه انجام می‌دهد؛ بستهٔ انتشار، ZIP، EXE مستقل یا تصویر منتشر نمی‌شود.

## امکاناتی که در نسخهٔ اجرایی محلی کار می‌کنند
- ثبت، ویرایش و حذف مشتری؛ حذف مشتری دارای سابقهٔ فاکتور مسدود است.
- ثبت، ویرایش و نگهداری کالای انبار؛ ورود موجودی و جلوگیری از صدور فاکتور بیش از موجودی.
- صدور فاکتور چندقلمی، محاسبهٔ مبلغ، مالیات واردشده و جمع کل با نوع عددی decimal.
- ثبت دریافت جزئی/کامل، محاسبهٔ مانده و جلوگیری از دریافت بیش از مانده.
- ثبت هزینه و گزارش خلاصهٔ فروش، دریافت‌ها، مطالبات و هزینه‌ها.
- کاردکس مالی شخص با ماندهٔ اول دوره، فیلتر تاریخ شمسی، گردش بدهکار/بستانکار از فاکتور/دریافت‌وپرداخت/چک مستقل، نمایش اطلاع‌رسانی حواله، خروجی CSV، چاپ جدول و گشودن پیش‌نمایش فاکتور مرجع. انتقال تمام انواع گردش قدیمی و هزینه‌های مستقیم به شخص هنوز باز است.
- کدینگ محلی حساب‌ها، ثبت دستی سند حسابداری دوبل (یک بدهکار/یک بستانکار)، دفتر روزنامه و تراز آزمایشی؛ ثبت خودکار پایه از فاکتور فروش/خرید، مالیات، بهای تمام‌شده، پرداخت‌ها و هزینه‌ها نیز وصل شده است، اما دفترکل چندردیفی و parity کامل با موتور مالی اصلی هنوز وجود ندارد.
- لغو فاکتور بدون دریافت و برگشت موجودی؛ فاکتور دارای دریافت را نمی‌توان با این عملیات لغو کرد.
- چاپ فاکتور از چاپگر انتخابی Windows و خروجی CSV با کدگذاری UTF-8.
- ذخیرهٔ خودکار محلی با DPAPI ویندوز برای حساب کاربری جاری؛ فایل داده در مسیر `%LOCALAPPDATA%\AshkeGhalam\WindowsNative\accounting-data.dat`.
- پشتیبان قابل انتقال با رمز انتخابی کاربر: AES-256-GCM و PBKDF2-SHA256؛ بازیابی قبل از جایگزینی، ساختار و صحت رمزنگاری را بررسی می‌کند.
- ورودی اعداد فارسی و عربی.
- اتصال و بررسی آنلاین لایسنس با همان مرجع HTTPS نسخه اصلی، دریافت کلید عمومی، اعتبارسنجی رسید RSA-SHA256، تطبیق کلید/فضای کاری/HWID/تاریخ/سهمیه و ذخیره رسید تأییدشده با DPAPI. این کار به معنی پیاده‌سازی کامل کنترل سهمیه/قابلیت در تمام ماژول‌ها نیست.

## وضعیت مهاجرت (۲۳ اکتبر ۲۰۲۶)
این نسخه موازی و آزمایشی است. مسیرهای فعال WPF در هر موردی به معنی برابری کامل با نسخهٔ اصلی نیستند. نگاشت منو به تب‌های واقعی اصلاح شده، تنظیمات دارای انتخاب تم روشن/تیره است و پروفایل‌های شرکت فضای کاری جدا دارند. بازبینی میدانی رابط روی رایانهٔ مالک، parity کامل کاردکس/چک/چرخهٔ فاکتور، آزمون پشتیبان چندشرکتی و ماژول‌های برچسب‌خوردهٔ «در حال مهاجرت» همچنان باز هستند.

## راه‌اندازی و اجرای آزمایشی
- گردش‌کار فعلی GitHub Actions بستهٔ قابل دانلود یا artifact منتشر نمی‌کند. برای اجرای واقعی WPF روی Windows 11، از سورس شاخهٔ `feature/windows-native-dotnet` استفاده کنید.
- اسکریپت اجرای آزمایشی محلی که پیش‌تر دریافت کرده‌اید، آخرین سورس شاخه را می‌گیرد، فونت وزیر را داخل پروژه قرار می‌دهد و `dotnet run` را اجرا می‌کند؛ داده‌ها را به مسیر آزمایشی جداشده هدایت می‌کند.
- اجرای مستقیم `dotnet run --project windows-native-dotnet/src/AshkeGhalam.Windows/AshkeGhalam.Windows.csproj` به‌تنهایی از مسیر عادی داده‌های WPF استفاده می‌کند؛ پیش از آن، از وجود فایل فونت `Assets/Fonts/Vazirmatn-Regular.ttf` مطمئن شوید.
- به‌ترتیب از «مشتریان» یک شخص و از «کالا و انبار» یک کالا بسازید؛ سپس از «فاکتورها» یک فاکتور نمونه ثبت و «پیش‌نمایش» را آزمایش کنید. از «کاردکس مالی شخص انتخابی» گردش را با تاریخ شمسی بررسی کنید.
- برای آزمون چندشرکتی فقط از دادهٔ آزمایشی استفاده کنید. دادهٔ قبلی به شرکت فعال فعلی منتسب می‌شود و فضای کاری شرکت‌های دیگر خالی شروع می‌شود. قبل از استفادهٔ عملی، بک‌آپ/بازیابی چندشرکتی را جداگانه بررسی کنید.

## مرزهای مهم نسخهٔ فعلی
این برنامه فعلاً یک **نسخهٔ عملیاتی محلی برای استفادهٔ محدود و آزمون موازی** است، نه جایگزین کامل سامانهٔ فعلی. دفتر دوبل، ثبت دستی سند یک‌بدهکار/یک‌بستانکار و ثبت خودکار اولیه برای فروش/خرید، مالیات، بهای تمام‌شده، پرداخت‌ها و هزینه‌ها را دارد؛ برای لغو فاکتور سند برگشتی حفظ‌کنندهٔ سابقه می‌سازد. این حسابداری هنوز از نظر رفتار و گزارش با موتور مالی اصلی تأیید تطبیقی کامل نشده است. ورود و مجوزهای سرور، ابطال فعال، همگام‌سازی ابری، چندکاربره/LAN، تطبیق بانکی واقعی، مالیات و اتصال‌های تجاری، امضای دیجیتال، دفترکل چندردیفی، دوره‌بندی/قفل سال مالی و مهاجرت امن داده از نسخهٔ فعلی هنوز کامل نشده‌اند. دادهٔ WPF فعلاً با وب یا Electron همگام نمی‌شود.

مبالغ بر اساس واحد پولی که خودتان وارد می‌کنید محاسبه می‌شوند؛ در تمام رکوردها یک واحد ثابت نگه دارید و نرخ مالیات را مطابق وضعیت قانونی و نیاز خود تعیین کنید. این نسخه هنوز از نظر تطابق کامل با موتور مالی نسخهٔ قدیمی تأیید نشده است؛ تا پیش از مقایسهٔ گزارش‌ها، نسخهٔ قبلی و بک‌آپ مستقل خود را حفظ کنید.

این خروجی بدون امضای تجاری Authenticode منتشر می‌شود و ممکن است Windows SmartScreen هشدار نشان دهد. فایل EXE و داده‌های محلی با فایل پشتیبان متفاوت‌اند؛ پشتیبان‌ها را جداگانه و در بیش از یک محل امن نگه دارید.

## بررسی سورس و آزمون‌ها
پیش‌نیاز ساخت: .NET 10 SDK و Windows Desktop targeting pack. GitHub Actions فعلی فقط این گام‌ها را اجرا می‌کند و هیچ فایل انتشار یا artifact قابل‌دانلود تولید نمی‌کند:

    dotnet restore windows-native-dotnet/tests/AshkeGhalam.Windows.Tests.csproj
    dotnet build windows-native-dotnet/src/AshkeGhalam.Windows/AshkeGhalam.Windows.csproj -c Release
    dotnet test windows-native-dotnet/tests/AshkeGhalam.Windows.Tests.csproj -c Release
    dotnet run --project windows-native-dotnet/src/AshkeGhalam.Windows/AshkeGhalam.Windows.csproj --configuration Debug

برای آخرین نتیجهٔ build و آزمون به [اجرای CI شاخهٔ مهاجرت](https://github.com/ehsanahangar2012-lgtm/acc1405-6-25/actions/workflows/windows-native-wpf-parity.yml) مراجعه کنید. گزارش ممیزی و جزئیات مهاجرت در [AUDIT.md](AUDIT.md)، [MIGRATION-PARITY-TRACKER.md](MIGRATION-PARITY-TRACKER.md) و [ARCHITECTURE.md](ARCHITECTURE.md) هستند.
